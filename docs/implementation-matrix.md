# Implementation matrix

Updated: 2026-08-20. This is an engineering status sheet, not a product-claim checklist. “Implemented” means a tested in-repository path; long-duration or deployment-specific evidence remains explicitly separate.

| Feature | Current implementation | Quality | Missing pieces | Action |
| --- | --- | --- | --- | --- |
| HTTP-first execution | Pure planner chooses `HTTP`, `HTTP_THEN_BROWSER`, or `BROWSER`; auto has a two-attempt ceiling. | Implemented and unit-tested. | Historical domain observations are advisory only and not yet persisted. | Keep HTTP as the mandatory first auto attempt. |
| Explicit decisions | Responses include requested/resolved strategy, reason, signals, costs, memory estimate, cache eligibility, backend attempts, and a timeline. | Implemented. | Estimated units are relative classes, not billing or capacity promises. | Calibrate estimates from reviewed soak data. |
| SPA detection and readiness | Deterministic shell analysis covers empty framework roots, module scripts, framework markers, loading placeholders, response type/status, and meaningful-text density. Browser extraction uses a bounded structural-stability wait. | Improved and regression-tested. | No universal readiness heuristic exists; application-specific selectors remain more precise. | Add reviewed fixtures when a new framework shape is observed. |
| SPA route discovery | Settled DOM discovery reads same-origin anchors, link roles, `data-href`, and non-destructive tab panels without submitting forms or executing arbitrary actions. | Implemented with bounded traversal. | It cannot safely infer routes hidden behind application-specific state changes. | Prefer sitemap/links; add opt-in typed interactions only with a strict action policy. |
| Main-content extraction | Semantic and density scoring removes navigation, ads, sharing, recommendations, and other chrome; Markdown preserves lists, tables, code, and absolute links. | Improved. | Publisher-specific layouts still require corpus review. | Measure with the 100–500 page semantic corpus. |
| Article and access model | JSON-LD/Open Graph metadata, readable text, word count, canonical URL, access status/scope/signals, and evidence-level provenance. | Implemented and unit-tested. | Access detection is evidence-based and may classify novel paywalls as unknown/open. | Add reviewed signals without claiming retrieval of restricted text. |
| Browser backend abstraction | Typed stock Playwright, Patchright, CloakBrowser, Camoufox, and Clearcote IDs share capability reporting, deterministic selection, backend/profile-keyed workers, admission, health, and recycling. | Implemented; Patchright and CloakBrowser browser-tested locally. | Camoufox/Clearcote launch is environment-dependent; Cloak licensing is operator-specific. | Run the backend verifier in the production Linux image. |
| Playwright Chromium | Warm bounded workers, isolated contexts, health/drain/dead states, process IDs/RSS, recycling, backoff, proxy support, and admin extensions. | Default and verified by unit/integration plus prior Linux Docker smoke. | Current Windows checkout cannot run the Docker validation. | Re-run Docker smoke and long soak on the production Linux image. |
| Patchright | Node-native driver pinned to `1.62.1`, using the existing Playwright Chromium `1.62.1`; enabled by default and selectable per fetch. | Implemented and browser-tested. | Long-duration Linux evidence is not yet published. | Include Patchright in the reviewed corpus and soak matrix. |
| `invisible_playwright` | Replaced by Patchright rather than adding Python and patched Firefox. | Decision implemented. | No Firefox anti-detection backend. | Track Patchright/Playwright version alignment on dependency updates. |
| CloakBrowser | Optional Node dependency, launch adapter, backend/profile-isolated pool workers, raw bounded fingerprint arguments, and humanization presets/overrides. | Implemented behind operator enablement and license acceptance. | Windows verification launched signed free binary `146.0.7680.177.5` through `/v1/fetch` with a raw fingerprint seed and `careful` humanization. Production Linux and the operator's licensed channel still require deployment validation. | Pin the binary version and run the backend verifier in each deployment image. |
| Camoufox | Optional MPL-2.0 Node adapter, separately provisioned Firefox, typed OS/locale/humanization/network controls, and profile-isolated workers. | Implemented; package and artifact preparation validated. | This Windows host started the binary but did not complete the Playwright handshake; Linux Docker validation is required. | Run `npm run prepare:camoufox` while building the Linux image, then run the backend verifier. |
| Clearcote | Operator-managed executable adapter with bounded fingerprint flags, launch timeouts, derived profile encryption, and error redaction. | Implemented without the vulnerable npm SDK. | The reviewed Windows binary failed its OS crypt initialization on this host; Linux validation and artifact provenance remain operator responsibilities. | Verify the official artifact digest and run the backend verifier in the deployment image. |
| Resource-aware admission | Queue uses measured workload estimates and hard reserve; browser pool reuses warm capacity and refuses new launches at soft pressure. | Implemented. | Estimates need Linux production calibration per backend/version. | Publish raw 1 h/6 h/24 h results before tuning defaults. |
| Worker observability | `/pressure`, `/readyz`, and metrics expose worker state, PID, RSS, contexts/capacity, jobs, failures, launches, crashes, recycling, and replacements. | Implemented. | PID tree measurements are authoritative only on supported Linux hosts; cgroup charge is preferred in containers. | Preserve admission-authority labels in every benchmark. |
| Cache | In-flight coalescing, memory LRU, disk cache, normalized identity, bounded objects, private-header bypass, and cache outcome metrics. | Implemented. | Cross-node invalidation/storage is not supplied. | Keep the single-node boundary explicit. |
| Session isolation | API-key ownership, isolated BrowserContexts, encrypted storage state, bounded TTL/artifacts, and optional live viewer. | Implemented. | Distributed reconnect and object-store lifecycle are operator systems. | Keep one live-session owner per instance. |
| HTTP SSRF resistance | Schemes/credentials/private ranges are rejected; all DNS answers are checked and pinned for each direct connection; every redirect is re-resolved and re-pinned. | Improved and regression-tested. | Explicit proxies must enforce equivalent DNS policy; browser DNS can still change after application checks. | Require a DNS-aware egress proxy/firewall in production. |
| Browser SSRF resistance | Every browser request is URL/DNS validated by the route interceptor, including subresources. | Defense in depth. | Application interception cannot provide connection-time DNS pinning inside Chromium. | Enforce network-layer egress policy for production workers. |
| Target and agent output bounds | HTTP bodies, rendered output, public agent/MCP reads, exports, downloads, assets, artifacts, and crawl limits are bounded. | Improved; security finding remediated in the worktree. | Limit values still require workload-specific tuning. | Keep adversarial size tests in CI. |
| Benchmark runner | Request/duration modes, target cycling, requested and actual strategy/backend counts, p50/p95/p99, reproducibility metadata, periodic memory/worker samples, and transition deltas. | Implemented; short wiring tests only in this checkout. | No current 1 h/6 h/24 h production Linux results. | Run controlled authorised targets and publish raw JSON. |
| Extraction corpus | 100–500 reviewed pages; Markdown include/exclude, length, links, article words/title/access/strategy, and provenance assertions. | Implemented runner and example schema. | Repository does not ship third-party traffic or fabricated fidelity numbers. | Curate and version an authorised corpus. |
| Distributed operation | SQLite, local artifacts/cache, queue, and live sessions are instance-local. | Explicitly unchanged. | Shared queue, metadata, artifacts, and session routing. | Treat as an operator architecture project, not an implicit capability. |
| Challenge, fingerprint, and humanization | Fetch and BrowserQL retry the requested/default backend, Patchright, Clearcote, Camoufox, and CloakBrowser once each. Options are typed and backend-scoped. | Implemented with bounded attempts and explicit result state. | No external CAPTCHA solver; a challenge may remain after every backend. | Measure authorized targets and keep `challengeRemaining` honest. |
| Human challenge handoff | Atomic headed session navigation, authenticated viewer, challenge/clearance status, bounded wait, and same-context storage persistence. | Implemented and integration-tested without exposing cookie values. | Requires the Docker VNC bridge for direct human control; the operator must be authorized for the target. | Validate the full manual interaction in the production Docker display. |
